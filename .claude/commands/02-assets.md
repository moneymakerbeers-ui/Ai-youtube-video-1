STAGE 02 - STYLE AND ASSETS. Follow CLAUDE.md §2 (H4, H6), §4. Video folder: `videos/<slug>/`.
RESUME: read `state.json`. Never regenerate an asset whose `manifest.json` entry exists and whose file validates. Check the ledger before any paid call.

BEFORE THE GATE (free work only)
1. STYLE. Write `style-bible.md` and `style-tokens.json`: topic read (subject, evidence type, emotional register, audience) → preset(s) from `reference/style-presets.md` → palette tokens (every text pair ≥ 4.5:1 and every graphic pair ≥ 3:1, computed with `python tools/contrast.py --tokens style-tokens.json`) · the four `dimensions` (palette family, texture, motion language, composition; vocabulary in `reference/style-presets.md`) · optional named `looks` · lighting logic · texture and grain · typography (licensed fonts; minimum text height from CLAUDE.md §4) · caption style · motion language (easing tokens) · a unifying grade (colour matrix + grain + vignette applied in code to every asset, so mixed sources look like one world) · "must not look like" list · rationale. Anti-clone check: compare with the last 3 files in `library/style-bibles/`; differ in ≥ 2 dimensions unless `channel.md` fixes brand constants; record the comparison. Render one style tile by code (palette, type, label, line weight, glow with grain), view it, fix it.
2. ROUTING. Derive the visual jobs from `scenes.json` entities and write `assets-plan.json`: per job the route (code | retrieved | generated_image | generated_video | reused) and why; priority (hero | support | background); estimated cost from `prices.json`; license need; how it works in both aspect ratios (a hero plate is composed so its subject sits in the central region and edges tolerate a 16:9 or 9:16 crop; verify by cropping both); fallback. Search `library/assets/` first.
3. BUDGET FIT. Sum the estimates: Higgsfield credits (+ a 25 % retry reserve) must fit the ceiling; ElevenLabs characters = script + Short delta lines, +25 % for retakes; other paid items. If over, downgrade in this order: backgrounds → code gradients and parallax; supporting plates → code or a cheaper model; fewer hero images; lower resolution. Never trade away truthfulness or license rigor. Write `spend-plan.md` (≤ 1 page): what each credit buys, what is traded off, the expected look.

CREATIVE PREVIEW (free, still before the gate)
4. Build the preview from the scene data and style tokens as they stand: `python3 tools/preview.py make --project videos/<slug>`. It writes `review/preview/`: the hero shot and the most data-heavy technical shot in both 16:9 and 9:16, the first complex transition as a short clip in both shapes (when the project has one), a voice sample in the draft voice, a contact sheet, `preview.md`. Assets that are not generated yet are labelled placeholders and timing is estimated; nothing here is a QA verdict. Look at the images (Read them), fix what is plainly wrong once, regenerate.

SPEND GATE AND PREVIEW APPROVAL (the only planned question of the whole run: one message)
5. Show the creator, in at most 8 lines: the preview paths · the look you expect and the main trade-off · per service, plan against ceiling: Higgsfield credits planned + reserve vs ceiling and balance · ElevenLabs characters vs quota (or "free local voice, nothing to spend") · music and stock · compute $0 · "approve / lower X / free-only".
   On approval: `python3 tools/preview.py approve --project videos/<slug> --note "<what they said>"` and, for each service they approved, `python3 tools/ledger.py --project videos/<slug> approve --service <higgsfield|elevenlabs|music|stock|compute> --ceiling N --unit <credits|chars|usd> --quote "<the plan line they saw>"`. Services they declined: `ledger.py decline --service …`, and the plan drops to the free path. Approving one service never authorises another (credits, characters and dollars are different currencies).
   No answer → build only the free assets, mark paid steps BLOCKED, stop; the pipeline will refuse to run (exit 5) until the preview is approved. Changing the look, the voice or the scene structure afterwards invalidates the approval and asks again; editing narration or layout does not.

AFTER THE GATE
6. CODE ASSETS first (SVG diagrams, maps, charts, textures, typography plates, grain and vignette overlays): reusable generators in `tools/` or `engine/assets/` parameterised by the style tokens.
7. RETRIEVED ASSETS: save the license page text or screenshot to `assets/_licenses/<id>.txt`, prepare the attribution, confirm the image truly shows what the narration says. Prefer public domain or CC0.
8. GENERATED IMAGES (approved only). QUALITY IS NOT THE DEFAULT: Higgsfield's `generate_image` defaults to `quality: low`, `resolution: 1k` (tested v3.1: a bare call returns a 0.25-credit draft). Always pass them explicitly: heroes `quality: high` + `resolution: 2k` (1080p video); supporting plates `medium`/`2k` or `high`/`1k`; never `low` for anything the viewer looks at. For a cut-out layer (parallax, nested transition) pass `background: "transparent"` and check the PNG has an alpha channel. Before the ledger intent run the tool's `get_cost` preflight with the SAME parameters and book THAT price (seen: high/2k 2.75 credits, low/1k 0.25); if the quote does not fit the ceiling, lower resolution before quality. Record `quality`, `resolution`, `background`, model and prompt in the manifest provenance. One at a time, each wrapped in the ledger: `ledger.py intent --key higgsfield:<assetId> --service higgsfield --estimate <credits>` (exit 4 = refused: not approved, over the ceiling or the retry is used up; 5/6 = an earlier request for this key must be resolved first) → generate → `ledger.py submitted --key K --job-id J` as soon as the job id exists → `ledger.py done --key K --actual N --file assets/<id>.png` (or `failed`). If the sandbox cannot download the result (the CloudFront URL is refused by the network allow-list: seen in v3.1), mark the asset BLOCKED, try the linked computer, otherwise ask the creator to download the files and attach them to the chat, and meanwhile use the code or free fallback; never fake a file and never pay again for an image already generated (its job id is in the ledger). Prompt = what it is + composition (central subject, room to crop) + the style-bible phrases + "no text, no labels, no numbers, no watermark". No living-artist or brand names. Preview the price, generate, then verify: size, alpha if needed, no text (tesseract if available), look at a phone-size contact sheet. At most 1 retry. Update the ledger. When a model supports reference images, use the first approved asset as the style reference. A multi-object sheet (several isolated objects on a plain ground, sliced by code) is allowed only when the objects are separable and the style tolerates cut-outs; otherwise generate single plates.
9. MANIFEST. Write `assets/manifest.json` (schema `ManifestFile`), resolve every entity `assetId` in `scenes.json`, write `credits.md` (file · route · tool/model · prompt · license · credits; totals vs ceiling). Then run `npx tsx schema/validate.ts project videos/<slug>` (the manifest is now part of the cross-file checks).
10. REVIEW. One contact sheet of all assets at phone size; fix or replace failures within the ceiling.

EXIT CHECKS: every entity that needs a visual resolves to a manifest asset · every retrieved asset has license evidence · every generated asset has tool + prompt · each service's ledger ≤ its approved ceiling and no request is left in `intent` or `submitted` · the creative preview is approved (`preview.py status`) · `style-bible.md` exists · no placeholder remains (or it is listed as BLOCKED).
