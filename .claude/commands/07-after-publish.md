STAGE 07 - AFTER PUBLISH. Video folder: `videos/<slug>/`. Run it a few days after upload, with data the creator provides (analytics export, pasted numbers, or an analytics tool if one is connected). Without data, stop and say which numbers are needed.

1. INGEST the numbers: for the long video the audience-retention curve with its intro (first 30 s), spikes and dips, average view duration and percentage, traffic sources if given; for each Short viewed vs swiped away, engaged views, average percentage viewed.
2. MAP times to scene IDs using `scenes.json` timing. For each notable dip or spike write what the scene was doing (hook, definition, transition, music change, jargon) and two possible readings; a spike can mean delight or confusion/rewatching.
3. COMPARE with this channel's earlier uploads (the creator's baselines), not with generic benchmarks. Say when the sample is too small to conclude anything.
4. WRITE `after-publish.md`: at most 3 observations, 3 hypotheses, 3 changes to try next time, each labelled observed or hypothesis. Append the same lines to `library/lessons.md`. If a QA threshold or default should change, say which and why.
5. Never state that a change caused a result. Never copy another channel's tactics.
